Orbio Guard begins with a tenant boundary. Cloudflare Access verifies the user, and a keyed locator routes that identity to one private SQLite-backed Durable Object. Every tenant gets isolated agents, budgets, activity, OAuth tokens, and gateway key.

Connect Orbio dynamically registers an OAuth client, uses authorization code plus P K C E, validates tenant-bound state on a dedicated callback hostname, and encrypts OAuth tokens with AES G C M. Gateway provisioning uses Orbio M C P. Existing keys are never replaced without explicit destructive confirmation.

Every agent request starts with a scoped Guard token. Only its complete hash is stored. Status, model policy, request ceiling, and remaining daily budget are checked before integer micro-dollars are reserved and before tenant credentials are decrypted.

Guard supports OpenAI Chat Completions, Anthropic Messages, and the Responses API used by Codex. The live Orbio catalog exposes four hundred and thirty models. Guard maps Codex metadata slugs to Orbio model IDs and translates text and function-tool events to the available gateway protocol.

Provider usage replaces each reservation with actual cost. Unpriced failures release it. Interrupted reservations are conservatively confirmed because Orbio may have processed the request. The ledger stores IDs, model, decision, cost, and time, never prompt or response content.

The release gate covers sixty nine automated tests, strict Node and Worker typechecking, responsive browser rendering, production builds, dependency audit, and GitHub Actions. Live verification covers OAuth registration, key lifecycle, tenant isolation, model discovery, Codex text and tools, and Cloudflare Access. Orbio provides the intelligence. Guard makes fleets safe.
